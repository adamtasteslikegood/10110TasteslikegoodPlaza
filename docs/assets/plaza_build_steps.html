10110 TastesLike Plaza — Prototype Build Steps

Godot 4 · 8 milestones · Phase 1 (weeks 1–3) + Phase 2 (weeks 4–6)

Phase 1 — Godot prototype  (weeks 1–3)
1
Install Godot 4 + first-person template
Download Godot 4 (~80MB, free). Open the built-in "First Person Shooter" demo. Walk around. That is your movement system — done before writing a line of code.
CharacterBody3D ← player body Camera3D ← mounted at head height CollisionShape3D ← prevents wall-clipping
~1 hourZero code to start
2
Grey-box the office layout
Use Godot's CSG tools to rough out the lobby, corridors, and 3–4 rooms with plain grey boxes. No textures, no art yet. Validate that the space feels right to walk through before investing in visuals.
CSGBox3D ← walls, floors, ceilings Area3D ← doorway proximity triggers NavigationRegion3D ← NPC pathfinding mesh
~4–6 hoursGDScript: minimal
3
Load employee directory as game data
Convert your .md agent files to JSON. Write a GDScript autoload that reads them at startup into a Dictionary. Each agent definition becomes a data object the NPC system draws from. This is the direct bridge between your existing directory and the game world.
func load_agents(path): var f = FileAccess.open(path, FileAccess.READ) return JSON.parse_string(f.get_as_text()) # result: { "systems-architect": { role, color, dept } }
~2 hoursJSON + GDScript
4
First NPC — proximity dialogue
Place Systems Architect in the server room. An Area3D around them fires a signal when the player enters. The HUD listens and shows a dialogue panel populated from that agent's JSON definition. This proves the core loop: walk up → interact → receive info.
func _on_proximity_entered(body): if body.is_in_group("player"): GameEvents.emit("npc_approached", agent_id)
~3 hoursGodot signals
5
Assistant chat UI overlay
A CanvasLayer (always-on-top 2D layer) holds the chat panel. Player toggles it with a key. For now it returns scripted responses. In Phase 2 this routes to a real API call. This is the player's persistent nav guide throughout the whole experience.
CanvasLayer Control ← panel root VBoxContainer ← message history LineEdit ← input field Button ← send
~4 hoursGodot CanvasLayer
6
Unlock gate system + building map
A GameState autoload singleton tracks completed tasks and unlocked floors. Completing a task fires an event; the relevant door unlocks; the HUD map updates. This is the tutorial gate mechanic — onboarding completion drives world expansion.
## game_state.gd (autoload) var unlocked: Array = ["lobby"] func complete_task(id): completed_tasks.append(id) GameEvents.emit("task_done", id)
~5 hoursAutoload singleton
Phase 2 — I/O bridge  (weeks 4–6)
7
Python WebSocket bridge
A small Python process runs alongside the game. Godot sends task requests over WebSocket; the bridge spawns your agent CLI, captures stdout, and returns JSON. The game receives it on the event bus and shows it in the inbox. This is the entire integration layer.
## bridge.py async def handle(ws): task = await ws.recv() proc = subprocess.run( ["claude", task], capture_output=True) await ws.send(proc.stdout) ## godot side ws.connect_to_url("ws://localhost:8765")
~1 dayPython + WebSocket
8
First live agent output in-world
Player walks up to Systems Architect, asks a real question. The request routes through the bridge to the actual claude-code agent. The response appears in the dialogue panel and logs to the inbox. This is the moment the game becomes the tool. Everything after is polish and expansion.
