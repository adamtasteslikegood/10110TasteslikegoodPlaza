## Vision

### 10x Check
Instead of building a full 3D first-person environment (which requires complex art, navigation meshes, and physics tuning), we pivot to a highly stylized 2.5D top-down RPG perspective (think Pokemon or Stardew Valley). This drastically reduces asset creation time and focuses entirely on the core interaction loop: walking up to an agent, seeing their portrait, and interacting via a chat interface. It acts as a visual "South Park cutout" skin over the real 137 CLI agents.

## Scope Decisions

| # | Proposal | Effort | Decision | Reasoning |
|---|----------|--------|----------|-----------|
| 1 | Use generic "Cardboard" sprite with color tints per department | S | ACCEPTED | Eliminates art bottlenecks immediately. |
| 2 | "Wait or Delegate" UX for complex tasks | M | ACCEPTED | Models real office dynamics; short tasks block, long tasks run in background. |
| 3 | Simulated Streaming (Typewriter effect) for dialogue | M | ACCEPTED | True streaming is too brittle for the Python bridge prototype; batch feels dead. |

## Accepted Scope (added to this plan)
- 2.5D Top-Down perspective (Godot 2D).
- 1 generic agent sprite asset, tinted dynamically by department color.
- 1 generic silhouette portrait for dialogue UI.
- Python WebSocket bridge enforcing synchronous execution with timeout protection.
- Godot dialogue UI implements "typewriter" effect to simulate streaming from full JSON response.
- Background task delegation UI for long-running processes (future phase).

## `D-020` — Layer 2 is the current frontend, not "the engine"

Layer 2 is **"the current frontend, which happens to be 2.5D Godot"** — not "the
Godot 4 engine".

**Rationale.** `D-005` (the bridge has zero UI awareness) and the swap test that
enforces it are only meaningful if the frontend is structurally a *slot*. Naming
Layer 2 after one implementation makes the rule read as an aspiration; naming it
after the role makes it read as architecture. This costs nothing today and is what
lets a CLI, a web UI, or the eventual 3D world drop in without touching Layers 3–4.

**Frontend-swap matrix** (adapted from `ALIGNED-SPEC-025` Document A §A.5, cited as
research):

| Frontend | Status | Consumes intents? | Renders how |
|---|---|---|---|
| 2.5D Godot | v0.x / v1.0, primary | Yes | Dialogue panel + typewriter |
| CLI | Possible now, useful as a test harness | Yes | stdout |
| Web UI | v2.0 candidate | Yes | DOM |
| 3D world | v2.0–3.0 | Yes | 3D scene |

**Swap test, restated as a review gate:** if replacing Godot with the CLI harness
would require *any* bridge change, the boundary has been violated and the change
fails review.

## `D-014` — bridge boundary stays conceptual until after M8

The bridge's responsibilities and boundaries are defined in prose. **No versioned
API contract is frozen before M8.**

**Rationale.** At pre-prototype stage a versioned contract ossifies decisions before
M8 has taught us anything about what the messages actually need to carry. Keep the
connective layer thin and let capability live in the agents.

**Reversal threshold** — the one thing that changes this answer: *a formal
multi-frontend need arriving before v2.0 — a web demo required for fundraising, say
— promotes the conceptual message shape to a versioned contract at that point.
Nothing else does.* Absent that trigger, the contract is a post-M8 deliverable
targeting v1.x.

## `D-025` — GDScript lives beside its scene

Scene scripts live next to the `.tscn` that owns them under `scenes/`
(`scenes/npc/agent_npc.gd` beside `scenes/npc/agent_npc.tscn`). The three autoloads
stay in `autoload/` as `CLAUDE.md` prescribes.

**Rationale.** `CLAUDE.md` originally listed `scripts/` as the home for GDScript
(`npc.gd`, `door.gd`, `assistant_overlay.gd`, `ws_client.gd`). That was written
before `scripts/` filled up with the Python tooling CI invokes by path —
`scripts/validate_specs.py`, `scripts/generate_agents_json.py`. Putting GDScript in
the same flat directory would mix two languages, two runtimes and two audiences with
no way to tell at a glance which files CI depends on.

Script-beside-scene is also ordinary Godot practice, so it is what a contributor
arriving from any other Godot project will expect to find.

**Recorded rather than silently applied** because it contradicts a layout that
`CLAUDE.md` states in writing, and an undocumented deviation is exactly the kind of
thing a later agent "corrects" back. `CLAUDE.md` is updated in the same change.

**Scope.** This is a decision about the 2.5D Godot frontend and dies with it, which
is why it belongs here rather than in
[`platform-decisions.md`](platform-decisions.md) — it fails that document's
frontend-replacement test.
